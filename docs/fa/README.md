## 1. معرفی

WP AI Factory یک ابزار محلی تحت وب برای مدیریت پروژه‌های تولید فایل‌های WordPress با کمک گردش‌کار دستی DeepSeek است. کاربر مشخصات سایت مشتری را ثبت می‌کند، برای یکی از مراحل پروژه پرامپت می‌سازد، آن را در رابط DeepSeek ارسال می‌کند و پاسخ ساختاریافته را به برنامه برمی‌گرداند. برنامه فایل‌های مجاز را در فضای کاری پروژه می‌نویسد و امکان مدیریت فایل‌ها و دریافت خروجی ZIP را فراهم می‌کند.

### مدل ارتباط با هوش مصنوعی

- برنامه در نسخه فعلی به API دیپ‌سیک متصل نیست.
- ورود به حساب DeepSeek از داخل برنامه انجام نمی‌شود.
- کاربر پرامپت را کپی کرده و در DeepSeek می‌فرستد.
- پاسخ JSON را کپی کرده و در بخش Import وارد می‌کند.
- اتصال، احراز هویت یا استخراج خودکار پاسخ از حساب DeepSeek وجود ندارد.

### هدف خروجی

خروجی اصلی، پوشه `wp-content` شامل قالب‌ها و افزونه‌هایی است که DeepSeek در پاسخ خود تولید کرده است. خود WordPress Core در خروجی قرار نمی‌گیرد.

## 3. معماری نرم‌افزار

برنامه با Flask اجرا می‌شود و از الگوی تفکیک Route، Service، Model و Template استفاده می‌کند.

### لایه‌ها

- **Routes:** دریافت درخواست‌های HTTP و نمایش صفحات.
- **Services:** منطق پروژه، پرامپت، پردازش پاسخ، فایل، پشتیبان و خروجی.
- **Models:** مدل‌های SQLAlchemy برای SQLite.
- **Prompts:** متن و دستورالعمل مرحله‌های DeepSeek.
- **Templates:** صفحات HTML مبتنی بر Jinja.
- **Static:** فایل‌های CSS و JavaScript.
- **Core:** توابع عمومی، امنیت مسیر و داده‌های اولیه راهنما.

### جریان داده

```text
Browser
  |
  v
Flask Routes
  |
  +--> Project / Prompt / Import / File / Export Services
  |                      |
  |                      v
  |                 SQLAlchemy
  |                      |
  |                      v
  |                   SQLite
  |
  +--> Workspace Files
  |
  v
Jinja Templates + Static Assets
```

### فناوری‌ها و نسخه‌های ثبت‌شده در requirements.txt

- Flask 3.0.3
- Flask-SQLAlchemy 3.1.1
- Werkzeug 3.0.3
- pytest 8.2.2

Python باید روی سیستم نصب باشد. نسخه دقیق Python در فایل وابستگی قفل نشده است.

## 4. پیش‌نیازها و نصب

### پیش‌نیازها

- Windows 10/11 یا سیستم‌عامل دارای Python
- Python و دستور `python` در PATH
- دسترسی نوشتن در پوشه برنامه
- مرورگر مدرن
- اینترنت فقط برای استفاده از وب‌سایت DeepSeek لازم است؛ اجرای محلی برنامه به اتصال اینترنت نیاز ندارد.

### نصب در Windows

1. فایل ZIP پروژه را Extract کنید.
2. وارد پوشه اصلی شوید؛ همان پوشه‌ای که `app.py` و `requirements.txt` در آن قرار دارند.
3. فایل `start.bat` را اجرا کنید.

فایل `start.bat` در صورت نبود پوشه `venv` یک محیط مجازی می‌سازد، آن را فعال می‌کند، وابستگی‌ها را نصب می‌کند و سپس `python app.py` را اجرا می‌کند.

### نصب دستی

در ترمینال داخل پوشه پروژه:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python app.py
```

اگر PowerShell اجرای اسکریپت فعال‌سازی را مسدود کرد، می‌توانید از Command Prompt استفاده کنید:

```bat
venv\Scripts\activate
```

### مسیرهای داده

برنامه هنگام اجرا پوشه‌های زیر را در کنار سورس ایجاد می‌کند:

- `instance/` برای دیتابیس SQLite
- `workspace/` برای فایل‌های پروژه‌های WordPress
- `exports/` برای فایل‌های خروجی
- `backups/` برای نسخه‌های پشتیبان

دیتابیس پیش‌فرض در `instance/wpai.db` قرار دارد.

## 5. اجرای برنامه

برنامه با اجرای `app.py` روی آدرس محلی زیر اجرا می‌شود:

```text
http://127.0.0.1:5000
```

در کد فعلی، Flask روی `127.0.0.1` و پورت `5000` اجرا می‌شود و `debug=False` است.

برای توقف برنامه، در پنجره ترمینال `Ctrl+C` را بزنید.

**نکته:** این تنظیم برای استفاده محلی طراحی شده است. برنامه را بدون بررسی امنیت، احراز هویت و تنظیمات محیطی روی اینترنت عمومی منتشر نکنید.

## 6. راهنمای کاربری

### 6.1 داشبورد

صفحه `/` خلاصه‌ای از پروژه‌ها را نمایش می‌دهد؛ از جمله تعداد کل، پروژه‌های فعال، پروژه‌های تکمیل‌شده، پروژه‌های اخیر و فعالیت‌های اخیر.

وضعیت‌های فعال در آمار شامل `requirements`، `architecture` و `generating` هستند. وضعیت تکمیل‌شده `completed` است.

### 6.2 ایجاد پروژه

از بخش پروژه‌ها گزینه ایجاد پروژه را انتخاب کنید و اطلاعات زیر را وارد کنید:

- نام پروژه: الزامی
- نوع پروژه
- توضیحات و نیازمندی‌های مشتری
- زبان وب‌سایت
- ترجیحات طراحی
- نسخه هدف WordPress
- قابلیت‌ها
- صفحات موردنیاز

انواع از پیش تعریف‌شده در فرم شامل فروشگاهی، شرکتی، شخصی، خبری، آموزشی، وبلاگی، خدماتی، نمونه‌کار و اختصاصی است.

اگر فهرست قابلیت‌ها یا صفحات خالی باشد، سرویس پروژه ممکن است مقادیر پیش‌فرض خود را ثبت کند؛ بنابراین برای ثبت دقیق نیازمندی‌ها، فیلدها را آگاهانه تکمیل کنید.

### 6.3 ویرایش، تکثیر و حذف

در فهرست پروژه‌ها می‌توانید پروژه را جست‌وجو یا بر اساس وضعیت فیلتر کنید. عملیات ویرایش، تکثیر و حذف نیز در Routeهای پروژه وجود دارد.

حذف پروژه، پوشه Workspace همان پروژه را نیز حذف می‌کند. پیش از حذف، از فایل‌های مهم خروجی یا پشتیبان تهیه کنید.

### 6.4 معماری سایت

در صفحه معماری، فهرست صفحات و قابلیت‌ها قابل ثبت است. با ارسال فرم، معماری به شکل JSON در دیتابیس ذخیره و تأیید می‌شود و وضعیت پروژه به `architecture` تغییر می‌کند.

نمونه مفهومی:

```json
{
  "website": ["Homepage", "About", "Contact"],
  "features": ["Blog", "Contact Form"]
}
```

تأیید معماری برای تولید پرامپت مراحل کدنویسی لازم است.

### 6.5 تولید پرامپت

در صفحه پرامپت پروژه، یکی از مراحل را انتخاب کنید:

1. تحلیل نیازمندی‌ها (`requirements_analysis`)
2. طراحی معماری (`architecture_design`)
3. طراحی UI/UX (`ui_ux_design`)
4. تولید قالب (`theme_generation`)
5. تولید افزونه (`plugin_generation`)
6. پیاده‌سازی امکانات (`feature_implementation`)
7. بازبینی کد (`code_review`)
8. بسته‌بندی نهایی (`final_packaging`)

پرامپت تولیدشده شامل اطلاعات پروژه، صفحات، قابلیت‌ها، ترجیحات طراحی، نسخه هدف WordPress و معماری ثبت‌شده است. تاریخچه پرامپت در دیتابیس نگهداری می‌شود.

در کد فعلی، مراحل `theme_generation`، `plugin_generation` و `feature_implementation` فقط پس از تأیید معماری مجاز هستند.

### 6.6 وارد کردن پاسخ DeepSeek

به صفحه Import پروژه بروید، پاسخ DeepSeek را در کادر قرار دهید و ارسال کنید.

پردازشگر تلاش می‌کند JSON را از پاسخ مستقیم یا بلوک Markdown مانند ` ```json ` استخراج کند. اگر JSON معتبر و فایل‌ها مجاز باشند، فایل‌ها در Workspace نوشته می‌شوند.

نتیجه Import می‌تواند موفق، ناقص یا دارای خطا باشد. تاریخچه Import در دیتابیس ذخیره می‌شود.

### 6.7 مدیریت فایل‌ها

در صفحه فایل‌ها، ساختار درختی پوشه پروژه نمایش داده می‌شود. فایل متنی را می‌توان مشاهده و ویرایش کرد یا حذف کرد.

هنگام ذخیره فایل موجود، محتوای قبلی در جدول نسخه‌ها ذخیره می‌شود. این موضوع با پشتیبان کامل پوشه متفاوت است.

### 6.8 راهنمای داخلی

بخش `/help` شامل دسته‌هایی برای شروع سریع، DeepSeek، مدیریت پروژه، WordPress، عیب‌یابی و FAQ است. مقالات اولیه هنگام اولین راه‌اندازی دیتابیس Seed می‌شوند.

جست‌وجوی فعلی مقاله‌ها بر اساس عنوان انجام می‌شود، نه جست‌وجوی کامل متن مقاله.

## 7. چرخه کار با DeepSeek

1. پروژه را ایجاد کنید.
2. نیازمندی‌ها و صفحات را ثبت کنید.
3. معماری را بررسی و تأیید کنید.
4. مرحله مناسب را در صفحه پرامپت انتخاب کنید.
5. پرامپت را کپی کنید.
6. آن را در گفت‌وگوی DeepSeek ارسال کنید.
7. از DeepSeek بخواهید خروجی را دقیقاً طبق قرارداد JSON ارائه کند.
8. پاسخ را کپی کنید.
9. پاسخ را در Import پروژه وارد کنید.
10. پیام نتیجه را بررسی کنید.
11. در صورت ناقص بودن، ادامه را در Batch بعدی دریافت و Import کنید.
12. پس از تولید فایل‌ها، ساختار را در File Manager بررسی کنید.
13. از بخش Export خروجی موردنیاز را بگیرید.

### نکته درباره پاسخ‌های طولانی

بهتر است هر پاسخ یک `batch_id` یکتا داشته باشد و فقط فایل‌های همان بخش را شامل شود. پاسخ‌های چندبخشی باید هر بار JSON مستقل و معتبر داشته باشند.

## 8. قرارداد JSON ورودی

قرارداد مورد انتظار در پرامپت‌های فعلی:

```json
{
  "project_id": "project-slug",
  "batch_id": "batch-001",
  "files": [
    {
      "path": "wp-content/themes/custom-theme/style.css",
      "content": "/* CSS content */"
    }
  ],
  "completed": false,
  "message": "More files will follow."
}
```

### فیلدها

| فیلد | نوع | توضیح |
|---|---|---|
| `project_id` | string | شناسه متنی پروژه؛ اگر ارسال شود باید با slug پروژه برابر باشد |
| `batch_id` | string | شناسه بخش پاسخ |
| `files` | array | فهرست فایل‌های تولیدشده |
| `files[].path` | string | مسیر نسبی فایل |
| `files[].content` | string | محتوای کامل فایل |
| `completed` | boolean | نشان می‌دهد DeepSeek کار را کامل اعلام کرده است یا نه |
| `message` | string | توضیح اختیاری |

### قواعد مسیر

- مسیر باید نسبی باشد.
- مسیر مطلق پذیرفته نمی‌شود.
- بخش `..` در مسیر پذیرفته نمی‌شود.
- فقط مسیرهایی که با `wp-content/` یا `docs/` شروع شوند مجازند.
- مسیر تکراری در یک پاسخ خطا ایجاد می‌کند.
- محتوای فایل باید رشته باشد؛ قرارداد اصلی همین نوع را انتظار دارد.

### نکته درباره فیلد completed

در Route Import، وضعیت پروژه بر اساس `completed` تغییر می‌کند؛ اما این فیلد به‌تنهایی بررسی نمی‌کند که تمام فایل‌های موردنیاز سایت واقعاً تولید شده‌اند. تکمیل واقعی باید با بررسی خروجی و اجرای پروژه وردپرس تأیید شود.

## 9. ساختار فایل‌های پروژه WordPress

فایل‌ها در این مسیر ساخته می‌شوند:

```text
workspace/<project-slug>/
```

ساختار نمونه:

```text
workspace/
└── my-site/
    ├── wp-content/
    │   ├── themes/
    │   │   └── custom-theme/
    │   │       ├── style.css
    │   │       ├── functions.php
    │   │       ├── index.php
    │   │       └── ...
    │   └── plugins/
    │       └── custom-plugin/
    │           └── ...
    └── docs/
        └── ...
```

این فقط نمونه است؛ ساختار واقعی به فایل‌هایی بستگی دارد که DeepSeek برمی‌گرداند.

**WP AI Factory خود WordPress Core را دانلود یا نصب نمی‌کند.** همچنین در نسخه فعلی نصب خودکار قالب یا افزونه در یک سایت وردپرسی انجام نمی‌شود.

## 10. مدیریت فایل و نسخه‌ها

### نسخه‌بندی فایل

هنگام بازنویسی فایل موجود از طریق Import یا ذخیره دستی، محتوای قبلی در جدول `project_versions` ذخیره می‌شود. شماره نسخه برای هر مسیر به‌صورت افزایشی محاسبه می‌شود.

### پشتیبان کامل

عملیات Backup یک کپی از پوشه پروژه در مسیر زیر ایجاد می‌کند:

```text
backups/<project-slug>/<timestamp>/
```

عملیات Restore فایل‌های نسخه پشتیبان را با `copytree(..., dirs_exist_ok=True)` به Workspace کپی می‌کند. این عملیات فایل‌های موجود را جایگزین می‌کند، اما فایل‌های اضافه‌ای را که بعداً ساخته شده‌اند الزاماً حذف نمی‌کند؛ بنابراین Restore فعلی معادل پاک‌سازی کامل و بازگردانی دقیق Snapshot نیست.

## 11. خروجی گرفتن

در صفحه خروجی پروژه چهار نوع خروجی تعریف شده است:

| نوع | مسیر خروجی | محتوا |
|---|---|---|
| `wp-content` | `<slug>-wp-content.zip` | پوشه wp-content با ریشه wp-content در ZIP |
| `theme` | `<slug>-theme.zip` | محتوای پوشه themes |
| `plugins` | `<slug>-plugins.zip` | محتوای پوشه plugins |
| `report` | `<slug>-report.html` | گزارش HTML فهرست فایل‌ها و اندازه آن‌ها |

فایل‌ها در پوشه `exports/` ساخته می‌شوند.

### نصب خروجی wp-content

1. از سایت مقصد نسخه پشتیبان بگیرید.
2. ZIP را استخراج کنید.
3. پوشه `wp-content` داخل خروجی را با مسیر `wp-content` سایت WordPress تطبیق دهید.
4. فایل‌ها را با روش امن و ترجیحاً ابتدا در محیط آزمایشی منتقل کنید.
5. افزونه‌های وابسته را جداگانه نصب و فعال کنید.
6. قالب را از پیشخوان WordPress فعال کنید.
7. صفحات، منوها، پیوندهای یکتا و تنظیمات افزونه‌ها را بررسی کنید.

ZIP خروجی جایگزین WordPress کامل نیست و تنظیمات پایگاه داده، محتوای واقعی سایت، رسانه‌ها یا اطلاعات محرمانه مشتری را خودکار ایجاد نمی‌کند.

## 12. پایگاه داده

پایگاه داده SQLite با Flask-SQLAlchemy مدیریت می‌شود. جداول اصلی:

| مدل | کاربرد |
|---|---|
| `Project` | مشخصات و وضعیت پروژه |
| `ProjectRequirement` | قابلیت‌ها و صفحات موردنیاز |
| `ProjectArchitecture` | معماری JSON و وضعیت تأیید |
| `ProjectFile` | متادیتای فایل، اندازه و checksum |
| `ProjectVersion` | محتوای نسخه‌های قبلی فایل |
| `PromptHistory` | پرامپت‌های تولیدشده |
| `ImportHistory` | پاسخ‌های واردشده و نتیجه Import |
| `ProjectActivity` | رویدادهای پروژه |
| `HelpCategory` | دسته‌بندی راهنما |
| `HelpArticle` | مقاله‌های راهنما |

### روابط

- هر پروژه چند Requirement دارد.
- هر پروژه حداکثر یک Architecture دارد.
- هر پروژه می‌تواند چند فایل، نسخه، پرامپت، Import و Activity داشته باشد.
- هر دسته راهنما چند مقاله دارد.

در شروع برنامه `db.create_all()` اجرا می‌شود. این روش جداول را ایجاد می‌کند، اما جایگزین سیستم Migration برای تغییرات پیچیده Schema نیست.

## 15. امنیت و محدودیت‌ها

### کنترل مسیر

تابع `safe_join` مسیر مطلق و بخش `..` را رد می‌کند و مسیر نهایی را در محدوده Workspace نگه می‌دارد. Parser نیز فقط مسیرهایی با پیشوند `wp-content/` یا `docs/` را می‌پذیرد.

### محدودیت‌های امنیتی فعلی

- برنامه در کد فعلی سیستم حساب کاربری و احراز هویت ندارد.
- کلید پیش‌فرض Flask در `config.py` مقدار ثابت دارد؛ برای هر محیط باید `SECRET_KEY` امن و محرمانه تنظیم شود.
- در کدهای بررسی‌شده، پیاده‌سازی CSRF protection مشاهده نشد.
- محتوای PHP/JS واردشده صرفاً به دلیل قرار گرفتن در JSON امن محسوب نمی‌شود.
- بررسی Syntax PHP در `validation_service.py` وجود دارد، اما این بررسی به‌صورت خودکار در مسیر Import اجرا نمی‌شود.
- در نبود PHP CLI، بررسی جایگزین فقط توازن ساده آکولادها را بررسی می‌کند و اعتبار PHP را اثبات نمی‌کند.
- بررسی امنیتی کامل، اجرای ایزوله، اسکن بدافزار و تست عملکرد WordPress در نسخه فعلی تأیید نشده است.
- گزارش HTML نام پروژه و مسیرها را در HTML قرار می‌دهد؛ برای داده‌های غیرقابل اعتماد باید Escape مناسب اعمال شود.

### توصیه عملی

پروژه تولیدشده را قبل از نصب روی سایت مشتری در یک WordPress آزمایشی و جداگانه بررسی کنید. از کد تولیدشده توسط مدل هوش مصنوعی بدون بازبینی استفاده نکنید. پیش از انتقال به سایت واقعی، از فایل‌ها و دیتابیس نسخه پشتیبان تهیه کنید.

## 16. عیب‌یابی

### برنامه اجرا نمی‌شود

- مطمئن شوید Python نصب است.
- از پوشه اصلی پروژه `start.bat` را اجرا کنید.
- خطای نصب وابستگی‌ها را بررسی کنید.
- در صورت نیاز دستورات نصب دستی بخش 4 را اجرا کنید.

### صفحه در مرورگر باز نمی‌شود

- مطمئن شوید ترمینال هنوز در حال اجراست.
- آدرس `http://127.0.0.1:5000` را وارد کنید.
- بررسی کنید پورت 5000 توسط برنامه دیگری اشغال نشده باشد.

### JSON نامعتبر است

- خروجی DeepSeek را با بلوک ` ```json ` درخواست کنید.
- مطمئن شوید JSON ناقص یا دارای متن اضافی نامتوازن نباشد.
- کوتیشن‌ها و کاماهای JSON را بررسی کنید.
- اگر پاسخ چندبخشی است، هر Batch باید JSON مستقل داشته باشد.

### مسیر فایل پذیرفته نمی‌شود

- مسیر باید با `wp-content/` یا `docs/` شروع شود.
- مسیر مطلق و `..` مجاز نیست.
- از کاراکترهای مجاز انگلیسی، عدد، خط تیره، زیرخط، نقطه و اسلش استفاده کنید.

### فایل در ZIP وجود ندارد

- ابتدا در File Manager وجود فایل را بررسی کنید.
- برای خروجی `wp-content` باید پوشه `workspace/<slug>/wp-content` وجود داشته باشد.
- برای خروجی Theme یا Plugins باید پوشه متناظر وجود داشته باشد.

### Restore دقیقاً پروژه قبلی را برنمی‌گرداند

در پیاده‌سازی فعلی Restore فایل‌های Snapshot را روی پوشه موجود کپی می‌کند و الزاماً فایل‌های اضافه فعلی را حذف نمی‌کند. برای بازگردانی دقیق، پیش از Restore از Workspace فعلی کپی بگیرید و در صورت نیاز پوشه را دستی پاک‌سازی کنید.

## 17. تست‌ها

پوشه `tests/` شامل تست‌هایی برای موارد زیر است:

- Backup Service
- Export Service
- File Service
- Helpers
- Models
- Parser
- Project Service
- Prompt Service
- Routes
- Security
- Validation Service

اجرای تست‌ها:

```powershell
pip install -r requirements.txt
python -m pytest -q
```

در آرشیو تحویلی، `run_tests.bat` به `requirements-dev.txt` ارجاع می‌دهد؛ اما این فایل در فهرست آرشیو موجود نبود. بنابراین اجرای مستقیم آن ممکن است با خطای نبود فایل مواجه شود. اجرای دستور بالا از `requirements.txt` روش جایگزین پیشنهادی است.

**نتیجه بررسی این آرشیو:** اجرای تست‌ها در محیط بررسی به علت نصب نبودن `Flask-SQLAlchemy` متوقف شد؛ بنابراین نتیجه موفق یا ناموفق بودن خود تست‌ها از این بررسی قابل اعلام نیست. ابتدا وابستگی‌ها را نصب و سپس تست‌ها را اجرا کنید.

## 18. وضعیت قابلیت‌های توسعه آتی

موارد زیر در برنامه اولیه مطرح شده‌اند، اما در سورس فعلی به‌عنوان قابلیت کامل قابل تأیید نیستند:

1. پیش‌نمایش واقعی سایت WordPress و راه‌اندازی Docker.
2. اجرای خودکار تست‌های PHP و WordPress در محیط Sandbox.
3. مقایسه گرافیکی نسخه فایل‌ها و رابط کامل Restore نسخه.
4. احراز هویت و چندکاربره‌بودن.
5. مهاجرت دیتابیس با Alembic/Flask-Migrate.
6. جست‌وجوی تمام‌متن در راهنما.
7. بررسی جامع امنیت و کیفیت کدهای تولیدشده.
8. نصب خودکار WordPress و افزونه‌های وابسته.
9. گزارش تست عملکرد و سازگاری قالب در مرورگرها.

این فهرست برای تفکیک قابلیت واقعی نسخه فعلی از نقشه راه آینده درج شده است.
